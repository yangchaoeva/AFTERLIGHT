# 港城首页、连续开场镜头与发车更新

## 修改

1. 航拍总长约 15 秒；末段使用与实时追尾镜头同一个 `chasePose`，落到玩家实际排位、路面坡度对应的位置、目标和 FOV。五次平滑曲线让结束时速度和加速度收敛。开场补光及雾效逐步回归比赛设置。跳过使用 1.2 秒过渡。
2. 首次加载直接创建 harbor 世界，首页标题、位置、距离、地图背景一致；coast 世界改为选择时按需创建，正确保留海岸专用世界生成器。
3. 赛道选择顺序为港城、海岸、山地。
4. 可用按钮统一悬停放大/抬升/亮度与阴影反馈，主要按钮 1.045 倍；按下收缩回弹，键盘焦点保留。精细鼠标启用 hover，触屏不依赖悬停；减少动态效果时关闭缩放。
5. 发车问题原因：旧逻辑起步即将双列车位改成三种目标车道，并在没有检查旁车的情况下横向超车。现在使用 14 m 同列排距、双列错位排位，渐进油门与短反应时间，起步保持各自车道；前车跟随基于保险杠间距和相对速度，后续超车检查相邻车道、后车接近以及换道走廊，并限制目标车道横移速度。

## 验证

- 41 项测试通过，生产构建通过。
- 三赛道 × 三档难度：八辆混合车型前 6 秒保持双列，0 次车间碰撞纠正；静止前车场景后车减速排队。
- 新排位下，三赛道三档难度八车均完成两圈。测试中的已完赛车辆继续行驶，与游戏运行逻辑一致，避免冻结在终点成为假障碍。
- 数值测试：航拍终点与第 1 / 第 8 排位的实时追尾镜头完全一致。
- 4180 正式构建浏览器检查：港城首页与排序、按钮 hover、三张地图进入比赛、自然落镜及按钮/键盘跳过，未捕获页面异常或 console error。
- 实测交接前后相邻帧镜头位移：港城自然结束约 0.00038 m，海岸跳过约 0.024 m，山地跳过约 0.041 m；不是切换到另一套镜头偏移。鼠标悬停主要按钮计算样式为 scale(1.045)、translateY(-3px)。
- 证据：`artifacts/start-flow/results.json` 及同目录的首页、落镜、发车截图。复现：`npm test`、`npm run build`、`node scripts/start-flow-qa.mjs`。

这些验证针对正常 AI 发车和控制流程；保留玩家驾驶与车间碰撞，不将赛车改成无碰撞模式。
